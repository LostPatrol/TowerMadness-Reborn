# P8 游戏品质与完整体验总体计划

基线：2026-10-13 的 P7 原生功能发布候选，main/a0f4f91。目标是在已有规则、资产和发布能力上，将功能原型推进为可以正常理解、操作和持续游玩的桌面游戏。

当前已推进P8.0及P8.1/P8.2首轮交互样板：终局命令修复、中文布局、原塔图标、浏览/取消、合法预览、升级对比/退款、暂停/重开确认和结算已接入。生产输入完整首关重放及三个窗口布局检查通过。P8.3/P8.4已接入分类纹理效果、原XYZ挂点、塔朝向/俯仰、原时间行走帧/转向、冻结尸体分段变换、敌人方向投影与护甲aura。尺寸/粒子/完整随机消费及动态表现仍待原作对照。尚未宣布品质样板或P8总体完成。

P7 的基础规则和加载检查通过，但本次独立验收判定游戏品质未通过。接下来以一个完整品质样板关卡带动渲染、交互、GUI和HUD建设，再扩展到全玩法；不更换引擎，不重新实现已恢复的规则，不以新增关卡数量替代品质进度。

## 目标与边界

- 保持 Windows x64 原生 EXE，一次解压后双击游玩；发布运行不依赖 Android 或模拟器。用户已允许使用 Android/ARM 环境对照原游戏，开发期按需要安装独立环境。
- 优先复用原美术、图集、图标、字体/材质和特效资源，保留原作风格；桌面界面按鼠标键盘适配，不机械照搬手机布局。
- 原作规则保真与桌面体验品质分别验收。没有真机对照时，不能将近似动画和新桌面界面描述为原作已精确恢复。
- 继续忽略购买验证与广告。默认保持静音；真实音频播放另行按用户要求验证。
- 本计划是持续推进的任务依据；沿用现有游戏实现，不自行生成 agent/task 文件。

## 第一交付目标

选择 PlainPlane 作为完整品质样板，跑通主菜单、进入关卡、选塔、建造预览、放置、选中、升级/出售、战斗、暂停/继续、失败/胜利和下一步操作。样板需包含最终使用的布局、美术和反馈，不用临时文字面板代替最终界面。

先在该样板上形成稳定设计和实现，再扩展到各科技、不同地图及所有武器。后续样例覆盖地空混合、护甲/特殊状态、大地图及不同环境，不能让首关样板成为唯一能正常显示的特例。

推进顺序：P8.0先完成；P8.1与P8.2一起组成交互样板；P8.3和P8.4逐步填满样板；P8.5完善外围流程；P8.6扩大覆盖。不要先把全部116关套上新菜单，就宣布GUI完成。

## P8.0 修正流程缺陷

直接修复Game及当前输入/UI对象：

- 在终局拒绝建造、升级、出售等需要继续仿真的命令；显示态同步，不只把按钮变灰。已建造的塔仍可查看详情。
- 根据资金、科技、建造中、升级中、出售中、已满级等状态决定按钮与快捷键是否可用，并告知原因。
- 定义操作层级：Esc优先关闭详情/取消建造，再进入暂停流程；退出通过明确菜单入口。重新开始提供避免误操作的确认或明确流程。
- 阻断菜单、弹窗、详情和设置区域的战场点击/滚轮/相机输入；处理右键拖动与取消操作的冲突及失焦后的拖动状态。

验收：自然胜负后鼠标和快捷键都不再扣费或创建永不完成的状态；操作UI不会误建塔或改变后台相机。只增加与这些实际缺陷相关的必要检查，不建立庞大交互测试框架。

## P8.1 统一GUI与HUD样板

先制定并实现一套清晰布局：

- 主菜单呈现游戏标题、开始/继续、关卡入口、设置与退出，使用可读关卡名和预览。
- HUD优先表达金币、羊/生命、当前与下一波、暂停/速度；战场保留足够面积，避免窄小地图和大量空白。
- 建造栏使用塔图标、短名称和成本；塔详情提供完整名称、空地资格、射程、攻击效果、建造状态、升级和出售。
- 统一字体、字号、间距、颜色及按钮默认/悬停/按下/选中/禁用状态。文本过长通过布局、换行或详情解决，不能一直缩小到不可读。
- 默认采用面向用户的中文文案，必要时保留原塔名对照。移除正常产品界面中的内部ID、original access gates are unverified等研发说明，说明留在开发文档。

原图标、nextwave/life/healthbar、按钮与字体图集优先核对后复用。初版不引入整套额外UI框架；先扩展现有Button/Text/SceneView所缺的最少能力。

验收：1280×900主布局与900×700最低窗口均可读、可点，详情不截断关键操作；主菜单、局内、暂停及结算使用同一视觉语言。提交真实运行截图和短操作路径供评审，截图好看不能替代实际点击测试。

## P8.2 完成操作与信息闭环

- 明确浏览、选塔建造、选中现有塔的状态；允许取消。普通观察或点击空地不能无意触发默认建造。
- 放置前显示半透明塔模型、占地、射程、价格及可建性。无效原因区分地形、重叠、资金、堵路等，颜色同时配文字，预览与实际Game判断一致。
- 提供升级分支的成本及效果对比、建造/升级进度和实际出售退款。不要将累计投资直接当作退款显示。
- 显示下一波计时与提前发波效果；资金不足和非法操作在操作附近反馈，底部错误长文本只作补充。
- 鼠标与快捷键走同一命令入口，按钮状态不会与快捷键行为矛盾。

验收：不了解快捷键的新玩家通过界面完成选塔、建造、取消、升级、出售、发波、暂停及重开；重复放置和高频选择不发生UI穿透或误建。保留既有寻路/资金/伤害规则，不通过修改数值让操作演示更容易成功。

## P8.3 战斗表现与可读性

- 表现事件携带攻击/特效类别、完整XYZ挂点、开始/结束时间及必要目标信息；激光/闪电起点连接真实炮口或上一链击目标。
- 逐类接入原beam、plasma、lightning、flame、烟尘、爆炸/核爆等资源。火焰、减速、链电、激光等不能最终共用同一红线；爆炸按类别和生命周期变化。
- 使导弹/炮弹朝向与完整3D轨迹对应，补炮口、尾迹、命中和范围效果。
- 展示敌人生命、受击、减速、眩晕、再生、增幅等必要状态。控制密度，避免每个单位永久覆盖大段数字。
- 给死亡、分裂、金币奖励、羊被抓走与失羊提供可见收尾。表现对象可在死亡后短暂保留，但不再参与攻击/寻路。

当前存在beam.model、lightning图集、shadowblob、nukeshockwave及smokepuff等资源，先核对原挂点、尺寸和时序。未证实的重建效果标为桌面表现近似。

验收：玩家仅凭画面能理解攻击对象、主要效果、击杀与失羊；12类武器逐项有与实际作用相匹配的反馈。表现随机不消耗战斗随机数；更换美术后，相同指令下的核心规则结果保持一致。暂停、倍速和恢复存档不重复伤害/奖励，表现时间不会与仿真脱离。

## P8.4 场景与动作品质

- 先复用接地阴影和天空/背景资源，改善单位与地面的空间关系，再决定是否需要更复杂的阴影技术；不预先建设PBR或复杂后处理。
- 核对地图、模型、纹理透明、材质混合与光照，处理关键透明层遮挡。纹理/模型已加载不等于最终效果正确。
- 恢复/核对行走帧率与朝向、转向/炮塔俯仰、动画插值和必要动作状态，避免离散换帧与突变。
- 默认镜头能看清出生、主要路径与羊圈；缩放/移动有适当范围，重置镜头明确。HUD与镜头共同保证战场可读。

验收：普通场景、不同环境及特效密集场景均能辨认敌人、塔与路径；真实挂点与渲染相符；不存在关键单位被UI遮挡、透明层异常或视觉残留。所有改动继续沿用现有资产/渲染器入口，避免另外做一套场景演示绕过游戏。

## P8.5 完整外围流程

- 关卡选择提供预览、难度/科技、完成记录和适当分类；包内附加关卡与战役区分，但不把研发说明放进用户流程。
- 暂停覆盖继续、重开、返回菜单、设置和退出；继续保存显示关卡、波次及保存状态。
- 胜负结算展示最终分数、剩余羊、战果及进度变化，并提供重试、下一关或关卡选择。终局后不再显示可执行的无效战斗操作。
- 自动保存、保存失败和继续失败显示简短可见的反馈；失败不破坏当前可用游戏。
- 音量控制仍保留默认静音；音频听感及真实播放需要另行覆盖，解码成功不能代替听感验收。

验收：无需开发说明即可完成启动→选关→战斗→结算→下一局，以及退出→继续。只有确实完成的关卡更新进度；原存档保留兼容，必要的版本迁移有说明。

## P8.6 全玩法扩展与发布验收

保留现有核心检查，不增加大量重复夹具。按新改动补少量有效验证，玩家体验用实际游玩和截图评审：

| 范围 | 验收方式 |
| --- | --- |
| 首关完整闭环 | 真实鼠标键盘完成一局胜利和一次失败，检查取消、升级、出售、暂停及结算 |
| 玩法覆盖 | 四科技、12类武器、地空混合、护甲/分裂/再生等代表场景；116模式维持全量加载检查 |
| 视觉覆盖 | 普通/大图、固定/开放路径、月球/熔岩等不同环境；检查场景、GUI及特效 |
| 窗口布局 | 900×700、1280×900、1920×1080；条件具备时实际验证125%/150%DPI，未覆盖如实注明 |
| 时间与保存 | 暂停、1/2/4倍速、失焦、保存恢复后无误操作或重复事件 |
| 性能与稳定性 | 完整自然关卡及密集无限局，记录分辨率、实体/表现对象数量和内存；不能复用轻负载高FPS声称全面通过 |
| 发布运行 | 独立目录双击EXE，含必要DLL和资产，不依赖开发工具；跨机器条件不足则注明 |

先完成一个真实高品质纵向样板，再扩大到全量。116模式加载成功仍不代表全部自然通关；可玩性、原作保真和发布兼容是不同的验收结论。

## 修改入口与任务拆分

| 功能 | 现有入口 |
| --- | --- |
| 菜单、HUD、输入与表现场景组装 | src/main.cpp |
| 按钮/文字/模型绘制与相机 | src/renderer.cpp、src/renderer.hpp |
| 终局、建造、出售、羊和流程状态 | src/game.cpp、src/game.hpp |
| 伤害、死亡/分裂与状态 | src/combat.cpp、src/effects.cpp |
| 炮口/轨迹/命中与表现事件 | src/projectile.cpp |
| 进度、局内恢复和设置 | src/profile.cpp、src/session.cpp |
| 资源准备与引用 | tools/prepare-assets.mjs、assets/data、assets/textures |

仅在main.cpp的场景组装和输入确实妨碍修改时，抽出必要的UI/表现文件；不为模块名齐全而大规模重构。保留原有Game为规则核心，以清晰的小接口连接输入和表现。

建议下一次任务完成P8.0与P8.1/P8.2的首个样板：先修复结束态缺陷，再交付最终布局中的建造/选择/详情/HUD和胜负流程。P8.3先覆盖首关激光及一种特殊效果，之后扩展全武器。每次任务交付运行截图、实际操作结论及差异清单，代码改动后生成独立报告并维护MEMORY。

工作量在首个品质样板完成后再评估；不把功能数量或测试条数作为“像一款游戏”的替代指标。
